# 航班信息系统：第一版

客户端和服务器均为 Python，只使用标准库，无需安装第三方依赖。已在 Python 3.13.9 / Windows 上验证。建议使用 Python 3.10 或更新版本。

实现范围：UDP、手工二进制消息格式、航线查询、航班详情、订座、限时监控回调、设置票价、延后起飞、两种调用语义、请求/回复丢失模拟、实验与测试。

## 1. 启动

在项目根目录打开终端：

```powershell
python -m flight_system.server --host 0.0.0.0 --port 6789 --semantics at-most-once
```

另开一个终端，同样进入项目根目录：

```powershell
python -m flight_system.client --host 127.0.0.1 --port 6789
```

客户端提供以下菜单：

| 编号 | 操作 | 示例输入 |
|---|---|---|
| 1 | 航线查询 | SIN → HND，返回 102 |
| 2 | 航班详情 | 102 |
| 3 | 订座 | 102，2 个座位 |
| 4 | 监控余量 | 102，60 秒 |
| 5 | 设置票价（幂等扩展） | 102，700 |
| 6 | 延后起飞（非幂等扩展） | 102，10 分钟 |
| 0 | 退出 | — |

航班 101 初始有 10 个座位，票价 500；102 有 20 个座位。另有 103（Singapore → Shanghai）和 104（新加坡 → 北京），用于不同航线和 UTF-8 测试。起飞日期从 2026-10-20 开始，所有日期展示为 UTC。服务器重启会恢复初始数据。

监控期间客户端不接受新请求，到期回到菜单；请在另一个客户端订座。服务器打印请求、参数、回复、丢包、缓存命中、回调及订阅到期日志。

## 2. 三台电脑演示

1. 三台电脑都准备好 Python 和本项目，使用能够相互通信的同一网络。
2. A 运行服务器，监听 `0.0.0.0:6789`。
3. 在 A 用 `ipconfig` 确认局域网 IPv4，例如 `192.168.1.20`。
4. B、C 启动客户端，把 `--host` 改成 A 的实际 IPv4 地址。`127.0.0.1` 只能用于本机测试，`0.0.0.0` 不能作为远程服务器地址。
5. B 选择菜单 4，监控航班 101 共 60 秒。
6. C 选择菜单 3，订航班 101 的 2 个座位；B 应显示 `seats: 8`。
7. 等到 B 监控结束，C 再订 1 个座位，检查服务器不再向该订阅发送通知。
8. 为验证多个订阅者，可在 C 另开一个客户端窗口也监控 101，再从其另一个窗口订座。

若网络不通，检查三台电脑能否相互访问、Python/UDP 是否被防火墙拦截，以及无线网络是否启用了客户端隔离。服务器使用固定端口 6789；客户端由系统分配临时 UDP 端口，并在同一个 socket 上接收回复和通知。

**当前自动验证在本机真实 UDP 上完成；三台实体电脑的网络与课堂演示仍需小组实际验收。**

## 3. 演示两种调用语义

先停止现有服务器，重新启动：

```powershell
python -m flight_system.server --semantics at-least-once --drop-replies 1
```

启动一个新客户端，**第一项操作直接订航班 101 的 2 个座位**。第一次回复被丢弃，客户端重传同一个请求，服务器再次订座，最终剩 6 个。

再停止并重新启动服务器：

```powershell
python -m flight_system.server --semantics at-most-once --drop-replies 1
```

启动新客户端，重复同样操作。最终剩 8 个，服务器日志会出现 `CACHE_HIT`。如果先做查询，第一条回复会被查询消耗，因此不能展示订座的重复执行问题。

参数说明：

| 程序 | 参数 | 说明 |
|---|---|---|
| server | `--semantics at-most-once` | 默认；另一种为 `at-least-once` |
| server | `--drop-requests 1,3` | 丢弃收到的第 1、3 个合法请求数据报 |
| server | `--drop-replies 1` | 丢弃第 1 次回复发送，包括缓存回复的发送 |
| server | `--request-loss 0.3` | 每个请求以 30% 概率丢弃 |
| server | `--reply-loss 0.3` | 每个回复以 30% 概率丢弃 |
| server | `--seed 42` | 固定模拟随机数种子 |
| client | `--timeout 0.5` | 每次等待回复的秒数，默认 0.5 |
| client | `--attempts 4` | 总发送次数上限，含首次发送，默认 4 |

两种模式使用相同客户端重传逻辑，调用语义在服务器启动时选择。显式丢包编号从 1 开始，重传也计数。回调不进入请求/回复丢包计数器。

**超时达到上限会报告结果未知，不能解释成订座失败。** 不要直接重新提交一个新的订座或延迟操作。可先查询当前状态；在有其他客户端修改时，查询也不能精确证明哪笔未知操作已执行。

## 4. 测试与实验

```powershell
python -m unittest discover -v
python -m flight_system.experiments
```

实验会启动临时服务器，使用真实本机 UDP，每组重置数据。输出在 `output/experiments/`：

- `RESULTS.md`：方便阅读的实验表格。
- `results.json`：完整结果、重试次数、耗时、丢包数。
- 每组独立 `.log`：客户端和服务器通信过程。

覆盖不丢包、首个请求丢失、首个回复丢失、全部请求/回复丢失、固定种子的随机丢包；分别验证订座、设置票价和延后起飞。再次运行将更新该目录下同名实验结果。

## 6. 第一版边界

- 航班、订阅和去重历史全部在内存。服务器重启后无跨重启去重保证。
- 历史保留至服务器退出，适合有限规模课堂实验，没有做长期运行的缓存清理。
- 回调尽力传输，带版本号过滤重复及乱序，但没有通知 ACK 或通知重传。
- 服务器从接受监控请求时计时；客户端从收到注册回复后等待相同长度。注册回复丢失或延迟时，客户端末尾可能存在没有通知的等待时间。At-least-once 重复执行注册可刷新服务器订阅到期时间；at-most-once 不刷新。
- 一条数据报最多 1200 字节，无分片/分页协议；当前样本数据在限制内。
- 无登录、支付、权限或数据库；扩展操作供实验使用。
